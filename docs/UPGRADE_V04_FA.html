شفاخانهٔ ایبک — راهنمای نسخهٔ ۰.۴

Aybek Ten-Bed Specialy Surgical Hospital
شفاخانه ده بستر جراحی ایبک · بستهٔ یکپارچهٔ آنلاین/آفلاین · نسخهٔ توسعه، نه محصول تأییدشدهٔ بالینی

برای شروع لازم نیست قبلاً پروژه‌ای روی کمپیوتر شما موجود باشد. یک ZIP جدید را دانلود و کامل استخراج کنید. دستورهای لینوکس، خروجی آزمون و متن گفتگو را در CMD یا PowerShell نچسبانید. فقط دستورهایی را اجرا کنید که در این راهنما داخل کادر دستور آمده‌اند.

۱. دقیقاً چه چیزی تحویل شده است؟

  • یک ZIP با سورس برنامه، ویزارد نصب فارسی، ویزارد فعال‌سازی، ۱۹ wheel ویندوز، راهنما و ده اسکریپت شماره‌دار PowerShell.
  • همان برنامه، همان API، همان اطلاعات و همان قابلیت‌ها در نصب آنلاین و آفلاین. آنلاین فقط روش دریافت وابستگی‌ها را تغییر می‌دهد؛ سرویس ابری و همگام‌سازی خودکار دو دیتابیس نیست.
  • پیش‌فرض نصب آفلاین است. هیچ فونت، کتابخانهٔ رابط یا CDN خارجی هنگام کار لازم نیست. پیوندهای بیرونی طبی به اینترنت احتیاج دارند.
  • پنج داشبورد با آمار واقعی و راهنمای سه‌مرحله‌ای: OPD، دواخانه، لابراتوار، رادیولوژی و بستری/مراقبت جراحی.
  • حساب صریح «مدیر + داکتر»، حساب‌های جداگانهٔ کارکنان، ده خانوادهٔ چاپ قابل‌ویرایش، ۲۰۰ شناسهٔ طرح قبلی و ده پالت شخصی محیط کار.
  • پیش‌نویس نسخه ← پیش‌نمایش ← ویرایش ← بازبینی و تأیید داکتر ← چاپ/PDF. طرح و مشخصات تأییدشده snapshot می‌شوند.
  • نمونه‌های ساختگی در دیتابیس جدا: ۲۰ مریض آموزشی، ده قلم آموزشی غیر دارویی، درخواست‌های تمرینی، دو بستری و یک کار پیگیری. هیچ دادهٔ واقعی یا نسخهٔ دوزدهی آماده داخل بسته نیست.
  • سلامت فایل‌های فهرست‌شده، SQLite، فضای دیسک و زمان ساخت بکاپ؛ هشدار دوره‌ای و راهنمای دستی.

داخل ZIP نیست: Python، نصب‌کنندهٔ مستقل EXE، کلید خصوصی مالک، دیتابیس واقعی، رمز آماده، ویدیو/صدای ضبط‌شده، PACS/DICOM، حسابداری کامل، موتور تشخیص یا دوزدهی بالینی اعتبارسنجی‌شده، سرویس ابری، همگام‌سازی، یا تعمیر خودکار دوسیه‌ها.

۲. پیش‌نیاز و محدودیت صادقانه

  1. Windows 64-bit و CPython 3.11 x64 باید قبلاً نصب باشد. بستهٔ wheel برای همین محیط است؛ Python 3.12/3.13، ARM و Python 32-bit هدف این بسته نیستند.
  2. اگر Python ندارید، آن را از منبع رسمی مورد اعتماد از جمله صفحهٔ رسمی Python برای Windows تهیه کنید. نسخهٔ سازگار و نگهداری امنیتی آن باید توسط مسئول IT بررسی شود. در نصب، Python Launcher و در صورت نیاز Add Python to PATH را فعال کنید. برای نصب کاملاً بدون اینترنت، فایل نصب معتبر Python را نیز جداگانه از قبل روی USB داشته باشید. این ZIP ویندوز خامِ بدون Python را به‌تنهایی آماده نمی‌کند.
  3. یک مرورگر جدید Edge/Chrome/Firefox، فضای کافی و اجازهٔ نوشتن در پوشهٔ نصب لازم است. نصب را در پوشه‌ای تازه و غیر از سورس انجام دهید.
  4. اجرای بومی PowerShell/ویندوز، میانبر Windows، صدای Windows و چاپگر فیزیکی در محیط ساخت آزمایش نشده‌اند. آزمون‌های Linux، مرورگر Chromium و حل وابستگی‌های هدف Windows جایگزین پذیرش روی کمپیوتر خودتان نیستند.
  5. پیش از اطلاعات واقعی: مسئولیت دسترسی، TLS، رمزگذاری دیسک/بکاپ، سیاست نگهداری، آزمون بازیابی، تأیید نسخه/نتیجه و پذیرش امنیتی/بالینی شفاخانه لازم است. یک فرآیند سرور و یک نویسندهٔ SQLite؛ چند worker یا چند کپی هم‌زمان روی یک فایل شبکه‌ای اجرا نکنید.

۳. آغاز از صفر — هر شماره یک اقدام

مرحلهٔ اول: فقط دریافت و استخراج

  1. ZIP نسخهٔ ۰.۴ را از همین گفتگو دانلود کنید؛ اگر فایل را نگرفته‌اید، هیچ دستور نصب اجرا نکنید.
  2. فایل ZIP را در پوشهٔ Downloads پیدا کنید. نام فایل را با نسخهٔ تحویل‌شده تطبیق دهید.
  3. از منوی راست‌کلیک، Extract All را بزنید و مسیر مقصد را E:\ انتخاب کنید. پوشهٔ نهایی باید چنین شود:
E:\Mamonaminyar-HMS-Print-Design-v4\
    Setup.cmd
    Start-Hospital.cmd
    release-manifest.json
    powershell\
    wheelhouse\
    docs\

اگر درایو E ندارید، از یک مسیر قابل‌نوشتن مثل C:\Hospital-Package استفاده کنید و مسیرها را متناسب تغییر دهید. ZIP را دوبارکلیک و برنامه را از داخل نمایش فشرده اجرا نکنید.

  1. در File Explorer وارد پوشهٔ استخراج‌شده شوید. اگر یک پوشهٔ هم‌نام دیگر می‌بینید، وارد پوشهٔ داخلی شوید تا Setup.cmd دیده شود.
  2. ساده‌ترین روش: Setup.cmd را دوبارکلیک کنید. این روش سیاست PowerShell را تغییر نمی‌دهد. پنجرهٔ بازشده را تا پایان نصب نبندید.

مرحلهٔ دوم: اگر می‌خواهید از PowerShell استفاده کنید

این روش جایگزین اقدام ۵ است، نه نصب دوم. ده اسکریپت را پشت سر هم و کورکورانه اجرا نکنید؛ بعضی فقط برای بکاپ، دیمو یا مالک است.

  1. PowerShell معمولی را باز کنید؛ معمولاً Administrator لازم نیست.
  2. فقط این دستور را وارد کنید:
Set-Location 'E:\Mamonaminyar-HMS-Print-Design-v4'
  1. برای دیدن فایل‌های همان پوشه:
Get-ChildItem
  1. در صورت نیاز، هش ZIP دانلودشده را با SHA-256 اعلام‌شده همراه تحویل مقایسه کنید. هش داخل همان ZIP به‌تنهایی اثبات هویت ناشر نیست. پس از اطمینان از منبع، فقط اسکریپت‌های همین بسته را از حالت مسدود دانلود خارج کنید:
Get-ChildItem .\powershell\*.ps* | Unblock-File
  1. اگر سیستم می‌گوید اجرای script ممنوع است، می‌توانید فقط برای همین پنجره سیاست محدود زیر را بگذارید؛ اگر سیاست سازمانی مانع شد، آن را دور نزنید و از مسئول IT یا Setup.cmd استفاده کنید:
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
  1. بررسی پیش‌نیاز و سلامت بسته:
.\powershell\01-Check-Package.ps1

اگر خطا داد، به بخش علت/راه‌حل بروید؛ مرحلهٔ بعد را اجرا نکنید.

  1. نصب آفلاین (روش پیش‌فرض):
.\powershell\02-Install-Hospital.ps1

یا، فقط اگر دانلود وابستگی‌ها را می‌خواهید، به‌جای دستور بالا:

.\powershell\02-Install-Hospital.ps1 -Online

مرحلهٔ سوم: تکمیل ویزارد فارسی

  1. در صفحهٔ «مسیر»، پوشه‌ای تازه مانند E:\Aybek-Hospital را برای برنامهٔ نصب‌شده انتخاب کنید؛ همان پوشهٔ ZIP/سورس یا پوشهٔ دارای دیتابیس را انتخاب نکنید.
  2. نام شفاخانه و انگلیسی را بررسی کنید. نام انگلیسی دقیق این تحویل Aybek Ten-Bed Specialy Surgical Hospital است. آدرس، تماس و خدمات واقعی را خودتان وارد کنید؛ سیستم اطلاعات فرضی را به‌عنوان تماس واقعی درج نمی‌کند.
  3. در صفحهٔ حساب، نام خودتان را وارد کنید. نام کاربری پیشنهادی owner است؛ می‌توانید عوض کنید. نام کاربری را یادداشت کنید، نه اینکه به نام فرضی داخل یک راهنمای قدیمی تکیه کنید.
  4. گزینهٔ «من هم داکتر هستم و هم مسئول شفاخانه» را در صورت صلاحیت خودتان روشن نگه دارید. این گزینه مسئولیت طبی می‌دهد؛ مدیر عادی خودکار داکتر نمی‌شود.
  5. رمز درخواستی شما را می‌توانید خودتان در دو کادر رمز وارد کنید: mamonaminyar. این رمز داخل برنامه ذخیرهٔ ساده یا به‌صورت پیش‌فرض نصب نمی‌شود؛ هش salted scrypt ذخیره می‌شود. چون رمز در گفتگو نوشته شده، برای دادهٔ واقعی رمز یکتای دیگری برگزینید و آن را به کارکنان ندهید.
  6. در بستهٔ فعلی، حالت «فعال‌سازی محلی» است؛ سریال اجباری یا کلید خصوصی آماده ندارد. اگر مالک بستهٔ مشتری امضاشده ساخت، فایل مجوز همان نصب در این صفحه انتخاب می‌شود؛ بخش مجوز را بخوانید.
  7. نصب را شروع کنید. پایان موفق، مسیر نصب و وضعیت آماده را بررسی کنید. قطع اینترنت در نصب آفلاین نباید مانع دریافت wheelهای همراه شود؛ نصب آنلاین به PyPI دسترسی لازم دارد.
  8. «اجرای شفاخانه» را بزنید یا در پوشهٔ نصب‌شده Start-Hospital.cmd را اجرا کنید. پنجرهٔ سرور را باز نگه دارید. با نام کاربری و رمزی که واقعاً وارد کردید وارد شوید.

۴. اجرای بعدی، دیمو و ده اسکریپت

دستورها را از پوشهٔ بسته می‌توانید اجرا کنید و InstallPath را به پوشهٔ نصب‌شده بدهید. اسکریپت‌های سه‌گانهٔ قدیمی در scripts برای سازگاری نگه داشته شده‌اند؛ راه تازه همین ده فایل شماره‌دار است.

شماره فایل در powershell کار واقعی
01 Check-Package بررسی Windows/Python و checksum؛ چیزی نصب نمی‌کند
02 Install-Hospital بازکردن ویزارد؛ پیش‌فرض آفلاین، -Online اختیاری
03 Owner-Account ایجاد اولیه فقط در DB خالی؛ یا اعطای صریح پروفایل داکتر به مدیر موجود
04 Create-Demo ساخت دیتابیس تازهٔ آموزشی؛ روی فایل موجود اجرا نمی‌شود
05 Start-Hospital اجرای محلی مرورگر؛ -Demo انتخاب صریح دیتابیس آموزشی
06 Health-Monitor بررسی فایل/دیسک/SQLite/بکاپ؛ -Watch هر ۳۰ دقیقه تا بستن پنجره
07 Backup snapshot تازه، بدون نشست‌های ورود؛ فایل مقصد موجود را بازنویسی نمی‌کند
08 Restore-To-New بازیابی به مسیر تازه با تأیید؛ دیتابیس اصلی جایگزین نمی‌شود
09 Owner-Licensing راهنما، ساخت کلید، صدور مجوز، ساخت ZIP مشتری با کلید عمومی
10 Verify-And-Guide checksum، pip check و بازکردن همین راهنمای آفلاین

اجرای معمول

.\powershell\05-Start-Hospital.ps1 -InstallPath 'E:\Aybek-Hospital'

بستن پنجره سرور را متوقف می‌کند. URL و پورت را launcher انتخاب می‌کند؛ شمارهٔ پورت را از نمونهٔ قدیمی حدس نزنید. این launcher فقط روی همان کمپیوتر و loopback کار می‌کند.

تمرین بدون آسیب به دیتابیس اصلی

یک‌بار اجرا کنید:

.\powershell\04-Create-Demo.ps1 -InstallPath 'E:\Aybek-Hospital'

برای دیمو رمز تازه را دو بار وارد کنید؛ چیزی روی صفحه نمایش داده نمی‌شود، طبیعی است. نام کاربری دیمو owner است، مستقل از انتخاب حساب اصلی. سپس:

.\powershell\05-Start-Hospital.ps1 -InstallPath 'E:\Aybek-Hospital' -Demo

دیمو در .data\demo.sqlite3 است؛ اصلی در .data\ash.sqlite3. اگر دیمو قبلاً ساخته شده، اسکریپت با خطا متوقف می‌شود و آن را بازنویسی نمی‌کند. دادهٔ آموزشی کاهش نمی‌یابد. برای دیموی تازه، IT باید یک مسیر تازه با CLI برگزیند؛ حذف کورکورانه لازم نیست.

حساب مدیر موجود که داکتر هم هست

نصب تازه از ویزارد کافی است. برای حساب قدیمی، نخست سرور را متوقف و بکاپ بگیرید؛ بعد با نام کاربری واقعی مدیر و تأیید GRANT:

.\powershell\03-Owner-Account.ps1 -InstallPath 'E:\Aybek-Hospital' -Username 'owner' -EnableExistingOwner

این دستور رمز را عوض نمی‌کند، مدیر جدید نمی‌سازد و سایر مدیران را داکتر نمی‌کند. اجرای صرف اسکریپت ۰۳ روی نصب موجود نیز حساب را بازنشانی نمی‌کند. فراموشی رمز باید با روند بازیابی مورد بازبینیٔ IT حل شود؛ رمز مخفی اضطراری داخل بسته نیست.

۵. کار روزمره — راهنمای عملی پنج بخش

پس از ورود، «داشبوردهای بخش‌ها» را باز کنید. هر کارت آمار واقعی همان DB را نشان می‌دهد. سه مرحله راهنماست؛ کلیک روی مرحله به‌معنی انجام آزمایش، معاینه یا تأیید طبی نیست.

OPD و نسخه‌نویسی

  1. «مریضان» ← «ثبت مریض». هویت، سن، جنس، وزن اندازه‌گیری‌شده، تماس و حساسیت معلوم را ثبت کنید. خالی به‌معنی عدم حساسیت نیست.
  2. از جستجوی نام/شناسه برای یافتن مریض استفاده کنید. لیست اصلی حداکثر ۱۰۰ نتیجه و انتخاب‌گر آخرین ۲۰۰ مریض را می‌بیند؛ برای مریض قدیمی جستجو و از ردیف همان مریض «نسخه» را باز کنید.
  3. «نمای دوسیه» ← ثبت معاینه. SOAP و علایم واقعاً بررسی‌شده را بنویسید. اصلاح یادداشت قبلی به‌صورت الحاقیه است، نه حذف تاریخچه.
  4. «نسخه جدید». شکایت، تشخیصِ خود داکتر و توصیه را وارد کنید. اگر ضرورت دوا نیست هیچ قلمی اجباری نیست.
  5. برای دواهای لازم «افزودن دوا». پیشنهاد نام از موجودی محلی است، نه تأیید ضرورت یا دوز. قدرت، شکل، دوز، دفعات، مدت، تعداد و هدایت را داکتر تعیین می‌کند.
  6. «بازبینی محدود» فقط کنترل‌های محدود متنی دارد؛ موتور جامع تداخل، تشخیص، دوز کودکان/حمل/کلیه/کبد یا رهنمود بالینی اعتبارسنجی‌شده نیست. مراجعه به منبع معتبر و تصمیم داکتر ضروری است.
  7. پیش‌نویس را ذخیره کنید؛ پیش‌نمایش باز می‌شود. طرح را ببینید. برای ویرایش، به پیش‌نویس برگردید و دوباره ذخیره کنید.
  8. پس از تطبیق هویت، حساسیت، ضرورت، دوز و دستور، تأیید داکتر را بزنید. فقط نویسنده مجاز به ویرایش/تأیید پیش‌نویس خویش است؛ مدیر بودن مجوز ویرایش نسخهٔ داکتر دیگر نیست.
  9. پس از تأیید، طرح چاپ از این صفحه قفل می‌شود و داده/طرح تأییدشده با تنظیمات بعدی عوض نمی‌شود. اصلاح سند تأییدشده با بازنویسی پنهان مجاز نیست؛ روند اصلاح بالینی رسمی خارج از این نسخه لازم است.
  10. چاپ/PDF ← کاغذ A4، scale 100%، header/footer مرورگر خاموش. طرح‌های عادی کوتاه در آزمون Chromium یک صفحه شده‌اند. متن بلند به صفحات بعد می‌رود؛ هیچ دوا برای یک‌صفحه‌کردن بریده نمی‌شود. پیش از تحویل، PDF و خروجی چاپگر خود را بررسی کنید.

دواخانه

با حساب pharmacy وارد شوید؛ نام، شکل، قدرت و موجودی واقعی را ثبت کنید. موجودی کمتر/برابر حد سفارش علامت می‌گیرد. برای ورود/خروج «تغییر موجودی» را با مقدار مثبت/منفی و علت ثبت کنید. سیستم این کار را رویدادنگاری می‌کند. مدیریت بچ، انقضا، فاکتور، قیمت و تحویل نسخهٔ کامل هنوز وجود ندارد؛ هشدار کم‌موجودی را با انبار واقعی تطبیق دهید.

لابراتوار

داکتر درخواست می‌دهد. کاربر lab فقط بخش مجاز خود را می‌بیند؛ هویت، عنوان و نمونه را کنترل و نتیجهٔ انجام‌شده را ثبت می‌کند. سیستم آزمایش اجرا یا نتیجه اختراع نمی‌کند. نتیجه نهایی از این صفحه قابل بازنویسی نیست؛ روند الحاقیهٔ نتیجهٔ رسمی هنوز پیاده نشده است.

رادیولوژی

همان مسیر درخواست/نتیجه با حساب radiology. بررسی ایمنی و تفسیر تصویر با فرد صلاحیت‌دار است. این بخش متن گزارش را نگه می‌دارد؛ PACS، ذخیرهٔ DICOM یا تشخیص خودکار تصویر نیست. کاربر lab نمی‌تواند نتیجهٔ رادیولوژی ثبت کند و برعکس.

بستری و مراقبت جراحی

داکتر/مدیر پذیرش بستری را با بستر ۱ تا ۱۰ ثبت می‌کند. کلیدهای یکتا مانع اشغال هم‌زمان همان بستر یا بستری فعال تکراری همان مریض می‌شوند. یادداشت مراقبت در دوسیه و ترخیص با یادداشت داکتر است. عنوان «مراقبت جراحی» به معنی وجود مدیریت کامل اتاق عمل، بیهوشی، رضایت‌نامه یا چک‌لیست WHO اعتبارسنجی‌شده نیست؛ آن ماژول‌ها توسعهٔ بعدی می‌خواهند.

حساب‌های کارکنان و امنیت

مدیر در «کاربران و نقش‌ها» برای هر فرد حساب جدا و نقش doctor، reception، pharmacy، lab یا radiology بسازد. گذرواژهٔ حداقل ۱۲ حرف و یکتا بدهد و از راه امن تحویل دهد. با غیرفعال‌سازی، نشست‌های آن حساب باطل می‌شوند. کارکنان را با حساب مالک شریک نکنید. «مدیر + داکتر» صریح، امکان کار بالینی خود مالک را می‌دهد، نه حذف مسئولیت یا کنترل نویسندگی.

۶. ده طرح چاپ و تنظیمات هوشمند

خانواده‌ها: آرامش بلورین، سپیدهٔ پاستلی، قاب قلب، نوار جراحی، موج ارکیده، افق هندسی، اطفال آرام، مینیمال فیروزه، نوشتار رسمی و امضای ایبک. تفاوت‌ها شامل ترتیب/ساختار هدر، قاب جانبی، نوار، انحنا، جدول، مشخصات مریض و امضاست، نه فقط رنگ. هشت تصویر شما الهام بصری بوده‌اند؛ نسخه‌ها، امضاها، واترمارک‌ها و نام کلینیک‌های مرجع کپی نشده‌اند. لوگوی رسمی مستقل از شما دریافت نشده؛ صلیب/قلب/AY نماد عمومی و قابل انتخاب است، نه ادعای لوگوی اصلی.

مدیر ← «ویرایش ده طرح چاپ»: عنوان، رنگ اصلی، wash، نشان، عنوان سند، یادداشت پایانی و تراکم را عوض و همهٔ ده طرح را ذخیره کند. اگر پیام تغییر هم‌زمان آمد، پیش از ذخیرهٔ دوباره صفحه را بارگذاری و تغییر مدیر دیگر را بررسی کند؛ سیستم بی‌صدا روی تنظیم تازه نمی‌نویسد. اجرای HTML/CSS/JS دلخواه از تنظیمات مجاز نیست.

مدیر ← «پروفایل شفاخانه»: نام، انگلیسی، تماس، آدرس، خدمات، وب‌سایت و ایمیل هدر/فوتر. اطلاعات قبلاً ذخیره‌شدهٔ یک نصب با ارتقا خودکار تغییر نمی‌کند؛ نام انگلیسی اصلاح‌شده را در همان پروفایل هم می‌توانید ذخیره کنید.

گالری: ۲۰۰ شناسهٔ قبلی حفظ شده، گروه‌بندی، جستجو و علاقه‌مندی وجود دارد. ۲۰۰ طرح، ۲۰۰ موتور طراحی مستقل نیستند؛ ترکیب‌های ساختاریِ ده مجموعه‌اند. این تحویل ده خانوادهٔ قابل‌ویرایش چاپ دارد؛ درخواست تاریخیِ بیست خانوادهٔ مستقل چاپ را انجام‌شده معرفی نمی‌کند. ده پالت «فضای شخصی» فقط رنگ محیط کار است، نه ده ساختار مستقل داشبورد یا نسخهٔ چاپی.

راهنمای زمینه‌ای در پنج ویزارد، هشدارهای سلامت، توضیح‌های فرم و این سند موجود است. ویدیو/گویندگی ضبط‌شده همراه بسته نیست؛ قابلیت صوتی فعلی، زنگ کوتاه هشدار است.

۷. سلامت، صدا و مهلت ۴۸ ساعت

  • سرور در آغاز و هر ۱۸۰۰ ثانیه بررسی می‌کند. فقط وقتی روشن است؛ برنامهٔ خاموش نمی‌تواند خودش هشدار بدهد.
  • SQLite quick_check، نسخه و وجود جدول‌های لازم؛ SHA-256 فایل‌های فهرست انتشار؛ فضای دیسک؛ زمان ساخت بکاپ اخیر کنترل می‌شود. فایل‌های نصب ورودی wheelhouse در بررسی زمان اجرا کنار گذاشته می‌شوند، اما Verify-And-Guide تمام manifest از جمله wheelها را بررسی می‌کند.
  • توسعهٔ مستقیم بدون manifest، وضعیت «not_available» برای checksum نشان می‌دهد؛ نباید آن را گواهی سالم‌بودن همهٔ فایل‌ها دانست.
  • فضای آزاد زیر ۳۰۰ MB هشدار، زیر ۱۰۰ MB بحرانی است. بکاپ ساخته‌نشده یا قدیمی‌تر از ۲۴ ساعت هشدار می‌گیرد؛ ساخته‌شدن به معنی ذخیرهٔ امن یا بازیابی موفق نیست.
  • مالک در «سلامت و هشدارها» علت و سه اقدام پیشنهادی را می‌بیند. «بررسی اکنون» به‌روزرسانی می‌کند؛ صفحهٔ سلامت و نشان سرصفحه نیز با polling تازه می‌شوند.
  • «فعال‌کردن و آزمون صدا» را شخصاً کلیک کنید. صدای کوتاه همان لحظه آزمون می‌شود. در تب باز، هشدارهای پاسخ‌داده‌نشده حداکثر هر ۳۰ دقیقه صدا می‌دهند. پس از خروج، اجازه/حالت صدا نگهداری نمی‌شود؛ مرورگر/OS می‌تواند صدا یا اجرای پس‌زمینه را محدود کند.
  • «دیدم و پیگیری می‌کنم» فقط تأیید دریافت است؛ مشکل را تعمیرشده اعلام نمی‌کند. ناظر وقتی بررسی بعدی سالم بود، رفع را ثبت می‌کند. پس از ۴۸ ساعت بدون پاسخ، هشدار به ارجاع دستی ارتقا می‌یابد؛ پیامک/ایمیل یا تیم پشتیبانی خودکار اعزام نمی‌شود.
  • تشخیص جامع فایل‌های اضافه/تکراری، همهٔ خرابی‌های آینده، همهٔ خطاهای سیستم‌عامل یا باگ‌های منطقی ادعا نمی‌شود. checksum جای آنتی‌ویروس، امضای ناشر، آزمون امنیت یا ممیزی بالینی نیست.
  • ناظر هیچ فایل، کد، نسخهٔ طبی، نتیجه یا رکوردی را خودکار حذف/اصلاح نمی‌کند. فقط وضعیت نگهداری و audit هشدار را ثبت می‌کند. تعمیر امن نیازمند بکاپ، نسخهٔ مورد اعتماد و تأیید انسانی است؛ کپی خودکار روی دیتابیس می‌تواند اطلاعات مریض را از بین ببرد.

برای کنترل جداگانهٔ فایل/DB و زنگ محلی، یک PowerShell دیگر باز کنید و نگه دارید:

.\powershell\06-Health-Monitor.ps1 -InstallPath 'E:\Aybek-Hospital' -Watch

این watchdog فایل/DB است، نه آزمون روشن‌بودن HTTP سرور. با Ctrl+C متوقف می‌شود. اگر خود دیتابیس آن‌قدر خراب باشد که وضعیت ذخیره نشود، دستور خطا می‌دهد؛ DB خالی جایگزین نمی‌سازد. برای availability واقعی، مانیتورینگ سرویس/HTTPS توسط IT لازم است. کنترل مرکزی چند سرور مجزا در این نسخه وجود ندارد؛ داشبورد مالک، وضعیت همان نصب را نشان می‌دهد.

۸. بکاپ، بازیابی و ارتقای نسخهٔ قبلی

بکاپ

از صفحهٔ بکاپ، فایل را دانلود و امن نگه دارید، یا:

.\powershell\07-Backup.ps1 -InstallPath 'E:\Aybek-Hospital' -Destination 'E:\Hospital-Safe-Backups\snapshot-01.sqlite3'

فایل مقصد باید تازه باشد. بکاپ snapshot سازگار SQLite است و نشست/تلاش ورود را پاک می‌کند؛ رمز حساب‌ها به‌صورت هش باقی می‌ماند. خود فایل بکاپ رمزگذاری نشده و دارای اطلاعات حساس است؛ روی حافظهٔ رمزگذاری‌شده و با دسترسی محدود نگهداری شود. یک کپی روی همان دیسک حفاظت در برابر خرابی آن دیسک نیست.

بازیابی آزمایشی

سرور را ببندید. با تأیید RESTORE به یک فایل جدید برگردانید:

.\powershell\08-Restore-To-New.ps1 -InstallPath 'E:\Aybek-Hospital' -Backup 'E:\Hospital-Safe-Backups\snapshot-01.sqlite3' -NewDatabase 'E:\Hospital-Recovery\recovered.sqlite3'

دیتابیس فعال خودکار عوض نمی‌شود. مسئول IT ابتدا بازیابی را با همان حساب، شمارش دوسیه‌ها و چند سند تطبیق کند. برای اجرای صریح فایل بازیابی‌شده، از پوشهٔ نصب‌شده در یک PowerShell تازه:

Set-Location 'E:\Aybek-Hospital'

$env:ASH_DB_PATH='E:\Hospital-Recovery\recovered.sqlite3'

.\.venv\Scripts\python.exe -m scripts.launcher

این انتخاب فقط برای همان پنجره است؛ launcher اکنون مسیر صریح ASH_DB_PATH را رعایت می‌کند. خروجی اصلی را حذف/جایگزین نکنید. پیش از انتخاب نهایی، مراقب باشید دو سرور به دو فایل متفاوت اطلاعات واقعی جدید نگیرند.

اگر از نسخهٔ ۰.۳ داده دارید

شما گفته‌اید هنوز پروژه‌ای نصب نکرده‌اید؛ برای شما این بخش لازم نیست. برای نصب‌های دیگر: سرور قدیمی را متوقف، snapshot بگیرید، پوشهٔ تازهٔ برنامه را با ویزارد بسازید و به‌صورت کنترل‌شده DB schema 2 قدیمی را با ASH_DB_PATH انتخاب کنید. این ارتقا ستون SQL تازه ندارد؛ تنظیمات جدید در settings است. اسکریپت نصب روی مسیر قدیمی اجرا و دیتابیس قدیمی را با DB خالی تازه عوض نکنید. schema 1 به مهاجرت صریح scripts.manage upgrade-v1 SOURCE NEW و آزمون نیاز دارد؛ هیچ مهاجرت پنهانی در startup انجام نمی‌شود.

۹. نصب روی کمپیوتر دیگر و سرور مرکزی

نصب مستقل: همان ZIP را کامل با USB منتقل کنید، Python سازگار را جدا نصب/بررسی کنید، ویزارد را در مسیر تازه اجرا کنید. حساب و فعال‌سازی مستقل دارد. برای آموزش script 04 همان دادهٔ نمونه را محلی می‌سازد. ZIP کلید خصوصی و دیتابیس اصلی شما را ندارد.

انتقال داده: فقط snapshot مجاز و امن را با روند بخش بازیابی منتقل کنید؛ .venv، کوکی مرورگر و فایل DB فعال را در حال کار کپی نکنید. نسخهٔ منتقل‌شده مستقل است و دو کمپیوتر خودکار همگام نمی‌شوند.

چند کاربرِ همان شفاخانه: یک سرور واحد و یک DB با حساب‌های جدا. launcher شخصی فقط loopback است؛ برای شبکه، مسئول IT باید host قابل‌دسترسی، فایروال، HTTPS reverse proxy، backup و ASH_SECURE_COOKIE=1 را تنظیم کند. مرورگر کارمند نباید به localhost سرور روی کمپیوتر خودش اشاره کند. سایت و API یک origin/مسیر نسبی دارند؛ هیچ URL مرورگر به localhost یک سرویس دیگر hardcode نشده است. سرور را مستقیم با HTTP روی اینترنت عمومی باز نکنید. راهنمای فنی docs/SETUP_FA.md را همراه محدودیت‌های نسخهٔ ۰.۴ بخوانید؛ تنظیم پیش‌نمایش Arena، پیکربندی تولید نیست.

۱۰. مالک، سریال و مجوز رایگان/پرداختی

بستهٔ تحویلی محلی و بدون کلید خصوصی است؛ پرداخت یا سریال ساختگی داخل آن نیست. صدور رایگان یا پولی تصمیم خود مالک است؛ نرم‌افزار درگاه پرداخت، جلوگیری صددرصدی کپی، ابطال آنلاین یا قفل‌کردن مراقبت طبی در انقضا ندارد. وضعیت/اعتبار مجوز بررسی می‌شود و wizard بستهٔ امضاشده مجوز معتبر می‌خواهد؛ انقضا نباید به‌عنوان تضمین قطع همهٔ دسترسی‌های بالینی معرفی شود.

  1. روی کمپیوتر امن مالک، script 09 با -Action KeyGen را اجرا کنید:
.\powershell\09-Owner-Licensing.ps1 -InstallPath 'E:\Aybek-Hospital' -Action KeyGen

کلید خصوصی را در مسیر خارج از برنامه و بسته، مثلاً حافظهٔ امن F:\Owner-Keys\issuer.pem بسازید. پوشه باید قبلاً موجود باشد. passphrase حداقل ۱۲ حرف را حفظ کنید، با کلید یا مشتری شریک نکنید. از کلید و passphrase بکاپ امن جدا بگیرید. ابزار کلید موجود را بازنویسی نمی‌کند.

  1. ZIP مشتری با کلید عمومی فقط بسازید:
.\powershell\09-Owner-Licensing.ps1 -InstallPath 'E:\Aybek-Hospital' -Action BuildCustomer

مسیر public key، فایل خروجی ZIP تازه و wheelhouse نصب‌شده استفاده می‌شود. این بسته همان عملکرد و اسکریپت‌های قبلی را دارد، اما wizard آن فعال‌سازی امضاشده می‌خواهد. هیچ فایل runtime، .data، .cache، کلید خصوصی یا رمز از سیستم مالک جمع نمی‌شود. این utility عمومی خودش کلید خصوصی تولیدشده را به مشتری نمی‌دهد؛ بدون کلید مالک، قادر به جعل امضا نیست.

  1. مشتری ویزارد را باز می‌کند و Installation ID همان تلاش نصب را برای مالک می‌فرستد؛ توکن URL نصب یا رمز حساب را نمی‌فرستد.
  2. مالک مجوز را صادر کند:
.\powershell\09-Owner-Licensing.ps1 -InstallPath 'E:\Aybek-Hospital' -Action Issue

نام مرکز، Installation ID، مدت اعتبار ۱ تا ۳۶۵۰ روز و مسیر JSON جدید خواسته می‌شود. مجوز شناسهٔ یکتا/امضای Ed25519 دارد؛ passphrase از stdin خواسته می‌شود نه آرگومان command line. فقط فایل مجوز را بفرستید. برای رایگان‌دادن، همین مجوز را بدون دریافت پول صادر کنید. ۵. مشتری در همان wizard فایل را انتخاب و نصب را تمام می‌کند. اگر wizard را از نو شروع کند Installation ID تازه می‌شود و مجوز قبلیِ نصب‌بسته ممکن است نپذیرد؛ مجوز متناسب صادر شود. تمدید از پروفایل شفاخانه/فعال‌سازی با فایل معتبر انجام می‌شود.

403 / توکن محافظتی نقش نامجاز، نشست/CSRF منقضی یا مسئول متفاوت حساب درست، ورود مجدد و صلاحیت نویسنده/بخش را بررسی؛ نقش را برای دورزدن عوض نکنید
تکمیل معاینه فقط توسط داکتر تعیین‌شده نوبت برای داکتر دیگری است همان داکتر پس از check-in تکمیل کند؛ مالک خودکار نویسندهٔ همهٔ معاینات نیست
409 تغییر هم‌زمان بازبینی فرم/تنظیم یا موجودی قدیمی شده داده را تازه و تغییر طرف دیگر را تطبیق؛ ارسال مکرر نکنید
Too many login attempts محدودکنندهٔ تلاش ورود صبر طبق سیاست؛ رمز واقعی و نام کاربری انتخاب‌شده را بررسی کنید
یک صفحه چاپ نشد متن بلند، تنظیم چاپ/فونت/مقیاس یا چاپگر متفاوت A4، ۱۰۰٪، هدر مرورگر خاموش؛ از تراکم مناسب استفاده و همهٔ صفحات را بازبینی کنید؛ متن دوا را حذف نکنید
صدا شنیده نشد اجازهٔ صوتی، mute، تب بسته/خواب OS در مرکز سلامت دکمهٔ آزمون؛ بررسی صدای مرورگر/OS؛ برای زنگ حیاتی به این برنامه تکیه نکنید
checksum در توسعه موجود نیست اجرای سورس بدون manifest بستهٔ انتشار را Verify کنید؛ نبود manifest تأیید تمامیت نیست
هشدار بکاپ بعد از دانلود فایل واقعاً ذخیره نشده/قدیمی، یا بررسی تازه نشده ذخیرهٔ امن و صحت snapshot را کنترل؛ بررسی سلامت اکنون را اجرا کنید
صفحه باز نمی‌شود سرور بسته، crash یا URL/پورت قدیمی پنجرهٔ سرور و اولین پیام خطا را بررسی؛ launcher را از نصب درست اجرا؛ فقط دادهٔ غیرحساس خطا را برای کمک بفرستید

برای درخواست کمک: نام اسکریپت/مرحله، Windows، نسخهٔ Python، مسیر بدون دادهٔ حساس و اولین پیام خطا را بفرستید. رمز، کلید خصوصی، توکن لینک نصب، DB و نام/معلومات مریضان را در گفتگو نفرستید.
