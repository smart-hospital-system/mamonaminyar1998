# دو بستهٔ جدا و ویزارد نصب / فعال‌سازی

نسخهٔ بسته‌های جدید: `0.3.0-workspace` — برنامه: `0.3.0` — schema: `2`

**بسته‌های این نسخه داخل `releases/v0.3.0/` هستند. فایل‌های هم‌نام در ریشهٔ `releases/` انتشار قبلی‌اند.** برای اطلاعات موجود، [ارتقای امن دیتابیس](WORKSPACE_V03_FA.md) را دنبال کنید؛ ویزارد، ارتقای خودکار مقصد غیرخالی انجام نمی‌دهد.

## فایل‌هایی که تحویل می‌گیرید

| بسته | هنگام نصب | هنگام استفاده |
|---|---|---|
| `ASH-Nexus-Online-Setup-win64-py311.zip` | وابستگی‌ها را از PyPI با اینترنت دریافت می‌کند | برنامه روی کمپیوتر شما اجرا می‌شود |
| `ASH-Nexus-Offline-Setup-win64-py311.zip` | از ۱۹ wheel همراه استفاده می‌کند؛ pip با `--no-index` اجرا می‌شود | برنامه روی کمپیوتر شما، بدون نیاز به اینترنت، اجرا می‌شود |

قابلیت‌های برنامه در هر دو یکسان است. **«آنلاین» در این بسته به معنی نصب با اینترنت است، نه سرور ابری، همگام‌سازی چند شعبه یا میزبانی عمومی.** لینک‌های منابع طبی بیرونی در حالت آفلاین بدون اینترنت باز نمی‌شوند؛ خود کتاب‌ها یا دانش جامع طبی در بسته نیستند.

## مرز مهم: این چه نوع Setup است؟

این انتشار، **ZIP دارای `Setup.cmd` و ویزارد گرافیکی در مرورگر محلی** است. فایل `Setup.exe` کامپایل‌شده، Windows Service، نصب‌کنندهٔ امضاشدهٔ ویندوز یا بستهٔ مستقل حاوی Python نیست.

پیش‌نیاز مشترک هر دو:

- Windows x64.
- **CPython 3.11 x64** همراه pip و venv، از قبل نصب‌شده.
- مرورگر جدید و اجازهٔ نوشتن در مسیر نصب.
- حداقل ۳۰۰ مگابایت فضای خالی.

Python برای بستهٔ آفلاین هم باید قبلاً روی کمپیوتر موجود باشد؛ نصب‌کنندهٔ Python همراه ZIP نیست. اگر «آفلاین» برای شما یعنی روی کمپیوتر بدون Python هم با یک EXE نصب شود، این انتشار هنوز آن شرط را برآورده نمی‌کند. آن مرحله نیاز به build و آزمایش روی Windows، بسته‌بندی runtime و در صورت انتشار عمومی، امضای کد دارد.

## نصب معمولی، قدم‌به‌قدم

۱. بستهٔ دلخواه را دانلود و **همهٔ ZIP** را استخراج کنید. مثال:

```text
C:\Downloads\ASH-Nexus-Offline\
```

۲. در پوشهٔ استخراج‌شده روی **`Setup.cmd` دو بار کلیک** کنید. آن را مستقیم از داخل ZIP اجرا نکنید. اجرای اسکریپت به تغییر سراسری PowerShell ExecutionPolicy نیاز ندارد.

۳. یک پنجرهٔ ترمینال و یک صفحهٔ مرورگر روی `127.0.0.1` باز می‌شود. پنجرهٔ ترمینال را تا پایان نصب باز نگه دارید. ویزارد به اینترنت عمومی bind نمی‌شود. اگر مرورگر خودکار باز نشد، لینک خصوصی چاپ‌شده در همان ترمینال را فقط روی همان کمپیوتر باز کنید؛ آن را برای دیگران نفرستید.

۴. ویزارد این مراحل را دارد:

1. **خوش آمدید:** نشان‌دادن نوع واقعی بسته؛ حالت آنلاین/آفلاین با تغییر یک دکمه به‌جای بستهٔ دیگر جا زده نمی‌شود.
2. **مسیر و پیش‌نیازها:** مسیر خالی و جدید، خارج از پوشهٔ استخراج‌شده انتخاب کنید. مسیر پیش‌فرض معمولاً `%LOCALAPPDATA%\ASH-Nexus` است. معماری Python، فضا، مجوز نوشتن و hash فایل‌ها بررسی می‌شود.
3. **مشخصات شفاخانه:** نام دری/انگلیسی، خدمات، تماس، ایمیل و آدرس.
4. **حساب مدیر:** نام، نام کاربری انگلیسی و رمز یکتای حداقل ۱۲ حرف با تکرار آن. رمز پیش‌فرض یا رمز مشترک داخل بسته نیست.
5. **فعال‌سازی:** در بستهٔ داخلی، تأیید محدودیت‌ها و راه‌اندازی اولیه؛ در بستهٔ تجاریِ سفارشی، انتخاب فایل فعال‌سازی امضاشده.
6. **مرور و نصب:** ساخت محیط مستقل، نصب وابستگی‌ها، بررسی pip، ساخت دیتابیس/مدیر، بررسی مدل‌ها و آماده‌سازی اجرا. رمز از stdin به worker منتقل می‌شود، نه آرگومان دستور یا فایل موقت.
7. **پایان:** فقط پس از موفقیت مراحل، پیام موفقیت و دکمهٔ اجرای برنامه ظاهر می‌شود.

۵. روی «اجرای ASH Nexus» کلیک کنید. سرور محلی روی یک پورت آزاد راه می‌افتد؛ launcher سلامت **همان فرایند** را بررسی می‌کند و سپس مرورگر را باز می‌کند. رمز ذخیره‌شده فقط hash است. با حسابی که خودتان ساخته‌اید وارد شوید.

۶. برای اجرای بعدی، از میانبر دسکتاپ یا **`Start-Hospital.cmd` داخل پوشهٔ نصب‌شده** استفاده کنید، نه نسخهٔ داخل پوشهٔ دانلود. پنجرهٔ سرور باید باز بماند؛ این انتشار Windows Service نیست.

۷. ابتدا فقط با دادهٔ آزمایشی کار کنید. تکمیل نصب یا فعال‌سازی به معنی تأیید بالینی نیست. برای ثبت نسخه، مدیر باید حساب جدا با نقش داکتر بسازد.

## نگهداری نصب قبلی و رفتار خطا

- مقصد دارای فایل یا دیتابیس موجود رد می‌شود. این ویزارد **upgrader یا migrator نصب قبلی نیست**.
- فایل‌های بسته براساس manifest و SHA-256 بررسی می‌شوند. این کار خرابی/کمبود فایل را تشخیص می‌دهد، ولی manifest بدون امضای ناشر به‌تنهایی تضمین اصالت ناشر نیست. checksum ZIP را از کانال مورد اعتماد مقایسه کنید.
- وابستگی ناموفق، فعال‌سازی نامعتبر یا خطای ساخت حساب نباید پیام «آماده» بدهد.
- اگر فقط اطلاعات حساب/فعال‌سازی رد شود، از «اصلاح اطلاعات» در همان ویزارد و همان مسیر دوباره تلاش کنید؛ وابستگی‌ها دوباره نصب نمی‌شوند.
- اگر ساخت محیط یا نصب dependency شکست بخورد، نصب ناقص باقی می‌ماند؛ برای شروع دوباره مسیر خالی جدید انتخاب کنید. ویزارد برای راحتی، پوشه یا دیتابیس را خودکار حذف نمی‌کند.
- اگر پس از ساخته‌شدن دیتابیس خطای فایل/دیسک رخ دهد، از آن داده نسخهٔ پشتیبان بگیرید و نصب را بررسی کنید. با پاک‌کردن کورکورانهٔ `.data` تلاش مجدد نکنید.
- ویزارد در حافظه کار می‌کند؛ بستن و بازکردن دوبارهٔ آن لینک و شناسهٔ نصب جدید می‌سازد. ادامهٔ فعال‌سازی یک نصب نیمه‌کاره پس از بسته‌شدن کامل ویزارد، خودکار پیاده نشده است؛ این انتشار نصب تازه را هدف می‌گیرد.
- میانبر اختیاری است؛ اگر ویندوز اجازهٔ ساخت آن را ندهد، نصب موفق باقی می‌ماند و می‌توانید `Start-Hospital.cmd` را باز کنید.

## فعال‌سازی: داخلی در برابر تجاری

### بسته‌های تحویلی فعلی: راه‌اندازی داخلی

دو ZIP عادی با حالت `local` ساخته می‌شوند. این حالت لایسنس اجباری ندارد. «فعال‌سازی» در آن یعنی نصب برنامه، ثبت هویت شفاخانه و ساخت حساب مدیر واقعاً تکمیل شده است. **سریال ثابتِ ساختگی یا DEMO-KEY به‌عنوان امنیت معرفی نمی‌شود.**

در صفحهٔ «پروفایل شفاخانه» وضعیت راه‌اندازی نشان داده می‌شود. فعال‌سازی، قابلیت طبی جدید یا دانش هوش مصنوعی تولید نمی‌کند.

### نسخهٔ دارای لایسنس امضاشده: نیازمند کلید مالک

زیرساخت فایل فعال‌سازی Ed25519 موجود است. برای انتشار این حالت، **مالک سیستم باید خودش کلید صادرکننده بسازد و نگهداری کند**. هیچ کلید خصوصی تجاری برای شما از قبل ساخته یا داخل بسته قرار داده نشده است.

روی کمپیوتر امن صادرکننده، با dependencyهای پروژه نصب‌شده:

```powershell
python -m scripts.license_admin keygen --private D:\SecureIssuer\issuer.pem --public D:\SecureIssuer\issuer.pub
```

این دستور passphrase حداقل ۱۲حرفی می‌خواهد و کلید خصوصی را رمزگذاری‌شده می‌نویسد. فایل‌های خروجی نباید از قبل موجود باشند. پوشهٔ امن را خودتان بسازید. کلید خصوصی و passphrase را جدا و آفلاین نگهداری کنید.

برای ساخت دو بسته با لایسنس اجباری:

```powershell
python -m scripts.package_releases --wheelhouse path\to\windows-wheels --output path\to\signed-releases --public-key D:\SecureIssuer\issuer.pub
```

فقط کلید **عمومی** در manifest قرار می‌گیرد. فایل خصوصی از allowlist انتشار حذف است. این فرمان در مسیر دارای ZIP هم‌نام، آن را بازنویسی نمی‌کند.

برای صدور فایل یک‌ساله:

```powershell
python -m scripts.license_admin issue --private D:\SecureIssuer\issuer.pem --organization "Aybek Hospital" --days 365 --output D:\Licenses\aybek.ashlicense
```

اگر لازم بود فایل به شناسهٔ نصب محدود شود، شناسه را از مرحلهٔ فعال‌سازی ویزارد بگیرید و پارامتر زیر را هنگام صدور اضافه کنید:

```text
--installation-id UUID-shown-in-wizard
```

این شناسه، شناسهٔ منطقی نصب است؛ fingerprint سخت‌افزاری یا حفاظت ضدکپی قفل‌شده نیست. فایل فعال‌سازی شامل payload امضاشده است و با دستکاری متن معتبر نمی‌ماند. نوع محصول، امضا، زمان صدور/انقضا و binding اختیاری بررسی می‌شوند.

بررسی امضا در هر دو بسته محلی است؛ هنوز سرور صدور/ابطال آنلاین، داشبورد فروش لایسنس یا اتصال پرداخت وجود ندارد. مالک به کاربر **فقط فایل `.ashlicense`** می‌دهد، نه کلید خصوصی یا passphrase.

برای تمدید نصب دارای کلید عمومی، مدیر در «پروفایل شفاخانه» فایل جدید را انتخاب می‌کند. انقضای لایسنس، دسترسی ضروری به سوابق مریضان را قطع نمی‌کند؛ وضعیت «نیاز به بازبینی» نشان داده می‌شود. این سیستم اثبات امضای فایل است، **نه DRM مقاوم در برابر صاحب دسترسی کامل به کد/دیتابیس**.

## ساخت دوبارهٔ بسته‌ها

```bash
python -m pip download --dest .cache/windows-wheels \
  --platform win_amd64 --python-version 3.11 --implementation cp --abi cp311 \
  --only-binary=:all: -r requirements.txt -c requirements-tested.txt colorama==0.4.6
python -m scripts.package_releases --wheelhouse .cache/windows-wheels --output releases/v0.3.0
```

خروجی‌ها شامل source، ویزارد، فایل شروع و manifest هستند؛ فقط نسخهٔ آفلاین wheelها را همراه دارد. دادهٔ مریض، `.data`، `.env`، محیط مجازی، کلید خصوصی، رمزهای preview و فایل بکاپ در بسته جمع‌آوری نمی‌شوند.

## چه آزمایش شده و چه نشده؟

آزمون‌های Python، رابط ویزارد، مجوز/توکن محلی، عدم پذیرش origin/Host غیرمجاز، تفکیک فرمان نصب آنلاین/آفلاین، حفظ مقصد موجود، پاک‌کردن درخواست حاوی رمز، خطای dependency و امضای لایسنس اجرا شده‌اند. نتیجهٔ نهایی و حدود تست در `docs/VERIFICATION.md` ثبت می‌شود.

بررسی resolver با `--no-index` برای wheelهای Windows انجام می‌شود، ولی اجرای واقعی `Setup.cmd`، ساخت میانبر COM و نصب روی ویندوز در این محیط لینوکس تأیید نشده است. پیش از تحویل عملیاتی، هر دو بسته روی ویندوز تمیز آزمایش شوند. این قید را با عبارت «نصب تضمینی روی همهٔ کمپیوترها» پنهان نمی‌کنیم.
