# ASH Nexus HMS — راهنمای نصب و استفادهٔ نسخهٔ پایهٔ واقعی

**نسخهٔ برنامه و بسته‌های جدید: ۰.۳ — schema: ۲**

> امکانات جدید، روش نوبت/دوسیه/معاینه و ارتقای دیتابیس قبلی در [راهنمای ۰.۳](WORKSPACE_V03_FA.md) آمده است. ZIPهای جدید داخل `releases/v0.3.0/` هستند؛ ZIPهای ریشه، نسخهٔ قبلی‌اند.

> برای دو بستهٔ مستقل آنلاین/آفلاین و ویزارد Setup، ابتدا [راهنمای نصب‌کننده‌ها](INSTALLERS_FA.md) را بخوانید. فرمان‌های این سند راه دستی/پیشرفته نیز هستند.

این نسخه از صفر در مخزن فعلی ساخته شده است. فایل‌های محیط قبلی در دسترس نبودند و ادغام یا export آن‌ها انجام نشده است. این یک پایهٔ قابل‌اجرا با ذخیرهٔ واقعی است، نه محصول دارای تأیید امنیتی/بالینی برای استفادهٔ عملیاتی شفاخانه.

## ۱. چه چیز واقعاً پیاده شده است؟

- Backend واقعی FastAPI و دیتابیس SQLite با فعال‌بودن foreign keyها و کنترل نسخهٔ schema.
- شناسهٔ یکتای مریض، ثبت و ویرایش مشخصات، جستجو، حساسیت و سابقهٔ طبی.
- حساب مستقل داکتر، پذیرش، دواخانه، لابراتوار و اکسری؛ مدیریت کاربران توسط مدیر.
- رمز scrypt با salt تصادفی؛ بدون رمز پیش‌فرض در برنامه یا بسته.
- نشست هشت‌ساعتهٔ سمت سرور، cookie با HttpOnly و SameSite، CSRF، خروج و ابطال نشست‌ها.
- تعویض رمز شخصی با ابطال تمام نشست‌های قبلی؛ غیرفعال‌کردن کارمند توسط مدیر.
- نسخهٔ طبی با اقلام ساختاریافته و ذخیرهٔ واقعی؛ ویرایش پیش‌نویس، کنترل تغییر هم‌زمان و تأیید توسط داکتر نویسنده.
- نگهداری مشخصات مریض، داکتر و شفاخانه هنگام تأیید نسخه؛ تغییر بعدی دوسیه یا پروفایل، محتوای سند تأییدشده را عوض نمی‌کند.
- ۲۰۰ ترکیب چیدمان چاپ A4 در ۱۰ مجموعه؛ جستجو و علاقه‌مندی شخصی؛ با ساختارهای متفاوت هدر، جدول، قاب، فاصله‌ها و فوتر؛ انتخاب طرح مشترک برای preview و چاپ.
- موجودی سادهٔ دوا با تغییر تعداد و علت؛ کاهش هم‌زمان موجودی به عدد منفی مجاز نیست.
- درخواست لابراتوار/اکسری توسط داکتر و نتیجهٔ نهایی توسط بخش مربوط؛ نتیجه در این نسخه بازنویسی نمی‌شود.
- ده بستر، جلوگیری از اشغال هم‌زمان و بستری فعال تکراری یک مریض؛ ثبت ترخیص توسط داکتر.
- آمار واقعی داشبورد، نه دادهٔ ساختگی؛ نمایش منوها براساس نقش، همراه با بررسی مجوز در خود API.
- ثبت رویدادهای مهم، snapshot سازگار SQLite و بازیابی به دیتابیس جدید با بررسی سلامت.
- رابط راست‌به‌چپ و فایل‌های کاملاً محلی؛ بدون نیاز به Node، CDN، مدل ابری یا فونت اینترنتی در زمان اجرا.

### هنوز چه چیز آماده نیست؟

موتور دانش طبی جامع یا RAG اعتبارسنجی‌شده، تشخیص و دوز خودکار، پوشش کامل تداخلات، مدیریت جراحی/بیهوشی، حسابداری و فروش، مدیریت بچ/انقضای دوا، ارسال/ذخیرهٔ عکس و ضمیمه، HL7/FHIR، امضای دیجیتال قانونی، نسخه‌بندی اصلاح نتیجهٔ معاینات، بکاپ زمان‌بندی‌شده، بازیابی آنلاین، نصب‌کنندهٔ مستقل شامل Python و ارزیابی امنیتی مستقل.

قابلیت‌های فهرست‌شدهٔ بالا **همهٔ خواسته‌های وسیع قبلی شما را تکمیل نمی‌کنند**؛ این مرحله یک زیرساخت واقعی و آزموده برای ادامهٔ کار است.

## ۲. پیش‌نیازها

برای بستهٔ آفلاین آماده‌شده:

- ویندوز ۶۴بیتی.
- **CPython 3.11 x64** از قبل نصب‌شده، همراه pip و venv.
- مرورگر جدید؛ چاپگر یا قابلیت Save as PDF مرورگر.
- اجازهٔ نوشتن در پوشهٔ پروژه.

خود نصب‌کنندهٔ Python داخل بسته نیست. wheelهای همراه مخصوص CPython 3.11 و Windows x64 هستند؛ برای Python 3.12، ARM یا سیستم دیگر، باید wheel مناسب همان هدف فراهم شود. وجود PowerShell و Python صحیح را با این فرمان‌ها بررسی کنید:

```powershell
python --version
python -c "import struct; print(struct.calcsize('P') * 8)"
```

خروجی مورد انتظار: نسخهٔ Python 3.11 و عدد `64`.

## ۳. نصب آفلاین قدم‌به‌قدم در ویندوز

۱. فایل ZIP را در یک پوشهٔ قابل‌نوشتن استخراج کنید. مثال: `C:\ASH-Nexus`؛ درایو E اجباری نیست.

۲. در پوشه‌ای که `requirements.txt` قرار دارد PowerShell باز کنید:

```powershell
cd C:\ASH-Nexus
.\scripts\Install-Windows.ps1 -Offline
```

اسکریپت محیط مجازی می‌سازد، فقط از `wheelhouse` نصب می‌کند، `pip check` می‌زند و برای ساخت مدیر از شما رمز می‌خواهد. رمز حداقل ۱۲ حرف باشد و برای این نصب یکتا انتخاب شود. رمز در ترمینال نمایش داده نمی‌شود. نام کاربری اولیه `admin` است.

**رمز پیش‌فرض وجود ندارد. رمز پیش‌نمایش این گفت‌وگو داخل بسته قرار نگرفته است.**

۳. اگر اجرای اسکریپت به علت policy سازمانی مسدود بود، policy سراسری را به Unrestricted تغییر ندهید؛ از مسئول سیستم اجازه بگیرید یا فرمان‌های معادل را اجرا کنید:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --no-index --find-links wheelhouse -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m scripts.manage init
```

پس از هر دستور، خطا را بررسی کنید؛ اگر نصب شکست خورد به مرحلهٔ بعد نروید. اجرای دوبارهٔ init روی دیتابیس موجود رد می‌شود و آن را بازنویسی نمی‌کند.

۴. سرور را اجرا کنید:

```powershell
.\scripts\Start-Windows.ps1
```

یا معادل آن:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

۵. مرورگر را روی `http://127.0.0.1:8000` باز کنید. با نام `admin` و رمزی که خودتان تعیین کردید وارد شوید. برای توقف سرور `Ctrl+C` بزنید.

`--no-access-log` عمداً استفاده شده است تا نام جستجوشدهٔ مریض در URL داخل access log معمول Uvicorn ثبت نشود. در reverse proxy نیز ثبت query و body حساس را غیرفعال کنید.

## ۴. نصب آنلاین / لینوکس

برای نصب آنلاین در ویندوز، `-Offline` را حذف کنید. نصب دستی روی لینوکس:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m scripts.manage init
.venv/bin/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

هیچ مرحله‌ای نیاز به npm برای اجرای محصول ندارد. npm فقط برای تست‌های DOM ابزار توسعه است.

## ۵. اولین استفاده

### مدیر سیستم

1. «پروفایل شفاخانه» را باز و نام، خدمات، تماس، آدرس، ایمیل و وب‌سایت را ذخیره کنید.
2. از «دیزاین اسناد» طرح پیش‌فرض را انتخاب کنید؛ انتخاب مدیر در دیتابیس ذخیره می‌شود.
3. در «کاربران و نقش‌ها» برای هر کارمند حساب مستقل بسازید. نقش داکتر را فقط به شخص دارای صلاحیت بدهید؛ این نرم‌افزار صلاحیت طبی یا جواز شخص را خودکار تصدیق نمی‌کند.
4. رمز اولیه را امن منتقل کنید و از کارمند بخواهید از آیکن سپر کنار حساب، رمز شخصی خود را عوض کند.
5. حساب مدیر خودش اجازهٔ تجویز ندارد؛ برای کار طبی از حساب داکتر جدا استفاده کنید.

### پذیرش

1. «مریضان و معاینات» ← «ثبت مریض».
2. نام، تخلص، سن، جنس و مشخصات لازم را وارد کنید.
3. حساسیت‌ها را با مریض بررسی کنید؛ خالی‌بودن این فیلد **به معنی نبود حساسیت نیست**.
4. ذخیره کنید و شناسهٔ `ASH-0000001` مانند آن را یادداشت کنید.
5. برای دوسیهٔ قدیمی با نام یا شناسه جستجو کنید؛ فهرست اولیه محدود به ۱۰۰ نتیجه است.

### داکتر — نسخه

1. با حساب داکتر وارد شوید.
2. مریض را جستجو و از همان ردیف «نسخه» را انتخاب کنید.
3. شکایت را بنویسید. پیشنهادهای محدود واژهٔ اعراض برای کمک تایپ است، نه تشخیص.
4. تشخیص، توصیه‌ها و در صورت ضرورت اقلام دوا را **خودتان** وارد کنید.
5. برای هر قلم، نام و قدرت، شکل، دوز، دفعات، مدت، تعداد و هدایت لازم را بررسی کنید.
6. «بازبینی محدود» فقط یادآوری‌های مشخص دارد؛ فقدان هشدار تأیید نسخه نیست.
7. پیش‌نویس را ذخیره کنید. می‌توانید آن را پیش از تأیید ویرایش کنید. اگر نسخه هم‌زمان تغییر کرده باشد، ذخیره با پیام تعارض رد می‌شود.
8. نسخه را مرور و در صورت درست‌بودن، بازبینی را تأیید کنید. فقط نویسندهٔ نسخه می‌تواند آن را تأیید کند.
9. سند تأییدشده در این نسخه قابل ویرایش نیست؛ جریان ابطال/اصلاح قانونی سند هنوز توسعه داده نشده است. خطای سند تأییدشده را در دادهٔ واقعی با دستکاری دیتابیس اصلاح نکنید.

### چاپ

- در بخش نسخه‌ها، «مشاهده و چاپ» را انتخاب کنید.
- طرح را در پیش‌نمایش تغییر دهید؛ انتخاب چاپ، محتوای طبی را تغییر نمی‌دهد.
- دکمهٔ چاپ، پنجرهٔ چاپ مرورگر را باز می‌کند؛ PDF روی سرور تولید نمی‌شود.
- کاغذ A4، مقیاس ۱۰۰٪، بدون header/footer اضافی مرورگر انتخاب شود.
- طرح رنگی ممکن است به فعال‌کردن Background graphics نیاز داشته باشد.
- نسخهٔ طولانی مجاز است چند صفحه شود؛ ردیف‌ها نباید برای جاگرفتن اجباری در یک ورق حذف شوند.
- پیش‌نویس علامت «تأیید داکتر ندارد» دارد.
- چاپ فیزیکی، صفحه‌بندی مرورگرهای مختلف و کیفیت فونت هنوز در این محیط آزمایش نشده است؛ ابتدا با اطلاعات آزمایشی روی چاپگر خود بررسی کنید.

### دواخانه، لابراتوار، اکسری و بستری

- دواخانه: قلم را ثبت و تغییر موجودی را با علت وارد کنید. این نسخه فروش، بچ و تاریخ انقضا را مدیریت نمی‌کند.
- داکتر: درخواست آزمایش/معاینه را ثبت کند؛ کاربر لابراتوار یا اکسری فقط در بخش خودش نتیجه می‌نویسد.
- نتیجهٔ نهایی دوباره نوشته نمی‌شود؛ گردش‌کار اصلاح نتیجه هنوز وجود ندارد.
- بستر: مدیر یا داکتر مریض را در بستر خالی ثبت می‌کند. ترخیص و یادداشت آن مخصوص داکتر است.

## ۶. بکاپ و بازیابی

### ساخت بکاپ

از صفحهٔ «بکاپ و بازیابی» و حساب مدیر دانلود کنید، یا:

```powershell
.\scripts\Backup-Windows.ps1 -Destination D:\SecureBackups\ash-2026-10-30.sqlite3
```

CLI مقصد موجود را بازنویسی نمی‌کند؛ نام فایل جدید انتخاب کنید. Snapshot از SQLite backup API ساخته می‌شود؛ نشست‌ها از کپی حذف می‌شوند و نشست‌های دیتابیس فعال دست‌نخورده می‌مانند.

**فایل رمزگذاری نشده است و شامل دادهٔ حساس، hash حساب‌ها و لاگ‌ها است.** از فضای رمزگذاری‌شده، ACL مناسب و محل پشتیبان جدا استفاده کنید. پوشه‌های `.data` و `backups` از Git کنار گذاشته شده‌اند، ولی این موضوع به‌تنهایی امنیت یا رمزگذاری ایجاد نمی‌کند.

### آزمون بازیابی

```powershell
.\.venv\Scripts\python.exe -m scripts.manage restore D:\SecureBackups\ash-2026-10-30.sqlite3 .data\restored.sqlite3
```

بازیابی فقط به مسیر **جدید و ناموجود** انجام می‌شود. برنامه header فایل، سلامت SQLite، foreign keyها، وجود جدول‌ها و نسخهٔ schema را بررسی می‌کند. فقط بکاپ مورد اعتماد خودتان را بپذیرید؛ فایل ناشناس قابل اعتماد نیست.

سپس سرور را متوقف کنید و در PowerShell:

```powershell
$env:ASH_DB_PATH = (Resolve-Path .data\restored.sqlite3).Path
.\scripts\Start-Windows.ps1
```

با حساب موجود در بکاپ وارد شوید؛ نشست‌های قبلی معتبر نیستند. تعداد مریضان، یک نسخه و چاپ را بررسی کنید. دیتابیس اصلی را تا تأیید موفقیت نگه دارید. برای بازگشت به مسیر پیش‌فرض پس از توقف سرور:

```powershell
Remove-Item Env:ASH_DB_PATH
```

بکاپ خودکار زمان‌بندی‌شده در این نسخه وجود ندارد. تا طراحی retention، رمزگذاری، اعلان شکست و آزمون بازیابی، نام «بکاپ خودکار مطمئن» روی آن نمی‌گذاریم.

## ۷. محدودیت دستیار طبی و منابع

این نسخه **مدل هوش مصنوعی یا موتور تشخیص ندارد**. ابزار فعلی شامل واژه‌نامهٔ کوچک اعراض، هشدار محدود وارفارین/اسپرین، نام تکراری دوا، یادآوری حساسیت و سن زیر ۱۸ سال است.

لینک WHO، DailyMed و NICE BNF برای مراجعهٔ دستی نشان داده می‌شود؛ محتوای آن‌ها به برنامه وارد نشده و این لینک‌ها به معنی اعتبارسنجی قوانین ما یا دسترسی آفلاین به آن منابع نیستند. مجوز و شرایط استفادهٔ هر منبع باید پیش از هر اتصال داده یا بسته‌بندی جداگانه بررسی شود.

- تشخیص قطعی، درمان، مقدار دوز، نسخهٔ عملیات یا پیشنهاد خودکار معاینات تولید نمی‌شود.
- سیرم، ویال، تابلیت یا آمپول اجباری در نسخه نیست.
- سن، جنس و وزن برای تجویز کافی نیستند؛ بارداری، عملکرد کلیه/کبد، حساسیت، راه مصرف و بسیاری عوامل دیگر لازم‌اند.
- هیچ اصلاح پنهانی نام دوا یا دوز انجام نمی‌شود.
- برای توسعهٔ بعدی باید منابع دارای مجوز، تاریخ/نسخهٔ مرجع، بازبینی متخصص و آزمون‌های بالینی مشخص اضافه شوند.

## ۸. امنیت و استقرار

- تا ارزیابی مستقل امنیتی و بالینی، فقط دادهٔ آزمایشی وارد شود.
- برای استفادهٔ محلی، سرور روی `127.0.0.1` است. آن را بی‌دلیل با firewall باز در اینترنت قرار ندهید.
- برای شبکه/میزبانی: reverse proxy دارای HTTPS، ACL، کنترل log، پشتیبان رمزگذاری‌شده و سیاست دسترسی لازم است.
- پشت HTTPS، `ASH_SECURE_COOKIE=1` تنظیم شود. با این مقدار روی HTTP محلی، مرورگر ممکن است cookie را ارسال نکند.
- مقدار `ASH_FRAME_ANCESTORS` به‌صورت پیش‌فرض `'self'` است. فقط در preview مورد اعتماد، originهای مشخص پلتفرم اجازه داده شوند؛ مجوز عمومی iframe ندهید.
- نشست پس از ۸ ساعت منقضی می‌شود؛ خروج، تعویض رمز و غیرفعال‌سازی کاربر نشست را باطل می‌کند.
- محدودسازی تلاش ورود ساده و مبتنی بر SQLite است؛ جای WAF یا ارزیابی امنیتی حرفه‌ای نیست.
- لاگ‌های برنامه tamper-proof نیستند؛ کنترل دسترسی سطح سیستم‌عامل و ذخیرهٔ مستقل رویداد برای محیط واقعی لازم است.
- schema نسخهٔ ۲ است؛ نسخهٔ قدیمی فقط با `python -m scripts.manage upgrade-v1 SOURCE NEW_DESTINATION` به فایل جدید ارتقا می‌یابد. برنامه خودکار schema قبلی را تغییر نمی‌دهد؛ [مراحل دقیق](WORKSPACE_V03_FA.md) را بخوانید.
- فراموشی رمز مدیر از طریق وب در این نسخه پیاده نشده؛ روش بازیابی حساب باید پیش از استقرار سازمانی طراحی و آزموده شود.

## ۹. آزمون‌ها و شواهد

اجرای مجموعهٔ Python:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest tests/integration tests/audit tests/setup -q
```

در محیط توسعهٔ لینوکس، **۵۴ تست یکپارچهٔ برنامه/فضای کاری + ۷ تست بازتولید ممیزی + ۱۴ تست نصب/لایسنس = ۷۵ تست موفق** بوده‌اند. یک هشدار Deprecation مربوط به TestClient/AnyIO وجود دارد؛ شکست تست نیست.

تست‌های DOM با دادهٔ شبیه‌سازی‌شدهٔ API:

```powershell
npm ci
npm test
```

**۲۰ تست رابط موفق (۱۵ برنامه و ۵ ویزارد)**؛ شامل محافظت از HTML ورودی، نبود دوای اجباری، نمایش و فیلتر ۲۰۰ طرح، درخواست ذخیره با CSRF و پاک‌کردن دادهٔ نمایشی هنگام خروج.

`requirements-tested.txt` نسخه‌های محیط تست را ثبت می‌کند. تست‌های Node برای اجرای عادی محصول لازم نیستند و بستهٔ آفلاین شامل `node_modules` نیست.

علاوه بر این، گردش‌کار واقعی در Chromium اجرا شد: ورود، ثبت مریض آزمایشی، ساخت/ویرایش/تأیید نسخه، تولید PDF برای هر ۲۰۰ طرح، نمایش دسکتاپ/موبایل و کارکرد منوی موبایل. هر PDF کوتاه یک صفحهٔ A4 بود؛ نسخهٔ طولانی آزمایشی ۶ صفحه شد و قلم آخر حفظ شد. هیچ خطای JavaScript صفحه در این مسیر ثبت نشد.

این شواهد معادل تست نفوذ، نصب روی ویندوز، تست چاپگر فیزیکی یا اعتبارسنجی بالینی نیستند. جزئیات اجرای مرورگر در [گزارش آزمون](VERIFICATION.md) است. resolver وابستگی‌های Windows x64 با `--no-index` بررسی شده است؛ نصب واقعی Windows در این محیط انجام نشده است.

## ۱۰. ساخت مجدد بستهٔ آفلاین

روی سیستم دارای اینترنت، برای همان هدف CPython 3.11 x64، wheelها را تهیه کنید. نمونهٔ cross-download از لینوکس:

```bash
python -m pip download --dest .cache/windows-wheels \
  --platform win_amd64 --python-version 3.11 --implementation cp --abi cp311 \
  --only-binary=:all: -r requirements.txt -c requirements-tested.txt colorama==0.4.6
python -m scripts.package_offline /path/to/ASH-Nexus-offline-win64-py311.zip \
  --wheelhouse .cache/windows-wheels
```

`colorama` صریحاً برای وابستگی ویندوز Click همراه شده است. بستهٔ آماده شامل source و ۱۹ wheel است؛ Python، اطلاعات مریضان، `.env`، دیتابیس، رمزهای preview و پوشه‌های مجازی داخل آن قرار نمی‌گیرند. برای انتشار بعدی، checksum فایل را پس از ساخت محاسبه و در کانال مطمئن به دریافت‌کننده بدهید.
