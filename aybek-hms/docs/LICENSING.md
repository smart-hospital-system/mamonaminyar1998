# Licensing and activation

The hospital belongs to **Dr. Mamon Aminyar**. Serials are generated by the
owner, are self-verifying and never require an internet connection.

---

## 1. How the trial works

* A 14-day trial starts with the **first sign-in** on a new installation.
* Every screen is fully functional during the trial — nothing is crippled.
* The header shows `Trial · Nd left`. At zero the hospital becomes read-only:
  you can still read, print, export and back up, but not create new records.
* Patient data is **never** deleted when a trial expires.

---

## 2. Serial format

```
AYBK - XXXX - XXXX - XXXX - CCCC
 |     |      |      |      |
 |     |      |      |      +-- checksum (SHA-256 of the first 12 characters)
 |     +------+------+--------- random groups, alphabet A-Z and 2-9
 +-------------------------------- product: Aybek HMS
```

The alphabet deliberately omits `0/O` and `1/I` so a serial can be read over the
phone without ambiguity. Because the last group is a checksum, a single wrong
character is rejected instantly — offline, without calling a server.

A valid serial looks like `AYBK-HSU5-2QHP-A9KH-MAGL`.
An invented one (`AYBK-AAAA-BBBB-CCCC-DDDD`) is rejected with
*“Checksum mismatch — this serial was not issued by Aybek.”*

## 3. Plans and seats

| Plan | Seats | Intended for |
|------|-------|--------------|
| trial | 3 | evaluation, 14 days |
| clinic | 10 | small clinic, OPD + pharmacy |
| hospital | 40 | the ten-bed surgical hospital (default) |
| enterprise | 250 | hospital group, several buildings |

A seat is one member of staff with a login. Adding a 41st user on a hospital
serial is refused until the licence is upgraded.

## 4. Activating

### From the interface
`/hms/activate` → paste the serial → **Activate this installation**.
The page shows the plan, the seat count and the machine it is bound to.

### From PowerShell
```powershell
.\aybek-hms\scripts\install\09-activate.ps1
```

### Generating serials (owner only)
`/hms/activate` → **Owner tools** → choose the plan and quantity → **Generate**.
Or from PowerShell:

```powershell
.\aybek-hms\scripts\install\09-activate.ps1 -Generate -Plan hospital -Count 3
```

The generated serials are shown once on screen and appended to
`aybek-hms\SERIALS.txt`. Keep that file private and add it to your own backup —
anyone holding a valid serial can activate a copy.

---

## 5. What “bound to the machine” means

On activation the machine name and a timestamp are stored in the licence
settings. Copying `data\slotly.db` to another computer copies the **data**, but
the new computer is not activated: it starts its own trial. This is intentional
— it keeps the hospital’s licence with the hospital’s computer.

Moving to a new computer? Activate it with the same serial. A serial may be
re-used by the owner on a replacement machine; nothing in the software blocks
it, and the licence register keeps both activations visible.

---

## 6. Revoking

On `/hms/activate`, the register lists every serial with its plan, seats, status
and issue date. A revoked serial still opens the *existing* installation (the
records must never be lost) but cannot activate a new one. Record the reason in
the register note so the decision is auditable.

---

## 7. If the licence is lost

The licence lives in the same database as the patients. If you restore a backup,
the licence is restored with it. If the database is rebuilt from scratch
(`03-seed.ps1 -Force`), the installation returns to a trial — re-activate with
the serial from `SERIALS.txt` or the printed certificate.

---

## 8. Honest limits

* The check is local and therefore not unbreakable by a determined programmer.
  It exists to keep honest installations honest and to record who owns which
  copy — not to fight a determined attacker.
* Nothing phones home. There is no activation server and no telemetry. This is
  the reason it works in a hospital with no internet.
