### فصل ENT تازه

- ۶۰ مدخل دوزبانه با ۱۱ فیلد: شناسه، ICD‑10، گروه، نام انگلیسی/دری، علایم، تشخیص، درمان، خلاصهٔ دری، علایم خطر و عوارض.
- موارد گوش، بینی، حلق، حنجره و سر و گردن؛ علایم خطر و عوارض برای هر ۶۰ مدخل ثبت شده‌اند.
- مدخل‌هایی که پیش‌تر در فصل عصبی یا تنفسی بودند (مانند وستیبولار نوریت، منییر و اپی‌گلوتیت) دوباره‌کاری نشدند.
- اسکریپت ساخت نسخه اکنون شناسه‌ها/نام‌های یکتا، ترتیب ENT، پوشش نسخه‌ها، داروهای ناشناخته، مسیر/شکل قطره‌ها و محتوای خطر را بررسی می‌کند.

### موتور نسخه و ایمنی

- `formulary.ts` — **۲۲۳** دوا/فرمولاسیون با باند کودک، بزرگ‌سال و سالمند. برای فصل ENT قطرهٔ گوش/بینی/چشم و شست‌وشوی نمکی افزوده شد؛ شکل و مسیر قطره‌های موضعی در هر سه باند کنترل می‌شود.
- `recipes.ts` — برای هر بیماری دستور نمونه وجود دارد. ۴۷۷ مورد قدیمی قالب نمایشی ۴ تا ۶ قلمی را حفظ می‌کنند؛ ENT عمداً **پرکردن خودکار ندارد** و اگر دوا لازم نباشد، فهرست دوا خالی می‌ماند. دواهای نامربوط صرفاً برای رسیدن به تعداد اضافه نشوند.
- `engine.ts` — ساخت نمونهٔ سنی/جنسیتی، محاسبهٔ مقدار و سهم هر دوا؛ موارد بدون دوا به‌درستی پشتیبانی می‌شوند.
- `safety.ts` — کنترل باند سنی، تنظیم کلیوی، تداخل و تکرار. هشدار فلوروکینولون کودکان فقط برای مصرف سیستمیک است؛ قطرهٔ گوشی/چشمی موضعی را اشتباهاً به‌عنوان مصرف سیستمیک علامت نمی‌زند.
- برنامه **وسیلهٔ طبی نیست و تصدیق بالینی ندارد**. دوزها نمونهٔ آموزشی‌اند؛ نبود هشدار سیستم، اثبات مناسب‌بودن دوا برای بیمار نیست.

### کاتالوگ در دیتابیس — `scripts/seed-catalogue.ts`

- فقط نمونه‌های دارای دوا درج می‌شوند: ۳۰۱۲ نسخهٔ `RX-C-####` و ۱۲۳۲۴ سطر دوا.
- ۲۱۰ نمونهٔ بدون دوا در مرورگر بیماری‌ها باقی می‌مانند و نسخهٔ خالیِ ساختگی نمی‌سازند.
- اجرای دوباره فقط ردیف‌های مالکیت این seeder را جایگزین می‌کند (`CT-####` و `RX-C-####`)، نه سوابق واقعی شفاخانه.
- `deploy.mjs` شمار مورد انتظار را از `data/disease-regimens.json` می‌خواند و در صورت اختلاف، seeder را برای تازه‌کردن کاتالوگ اجرا می‌کند.

**دیتابیس دمو پس از به‌روزرسانی:** بیماران ۳۰۳۸ · همهٔ نسخه‌ها ۳۰۲۲ · همهٔ سطرهای نسخه ۱۲۳۵۵ · دواهای انبار HMS ۳۲ · صفر نسخهٔ کاتالوگِ مسدودشده.

## ۳. لایسنس و امنیت

کلید امضای سریال از سورس بیرون است. ترتیب `resolveSecret`:

1. `AYBEK_LICENSE_SECRET` از محیط یا `.env.local`.
2. `data/license.key` — کلید محلی تصادفی، git-ignored.
3. کلید قدیمی فقط برای اعتبارسنجی سریال‌هایی که از قبل در `hms_licenses` ثبت شده‌اند؛ برای صدور استفاده نمی‌شود.

تست قبلی: سریال تازه معتبر بود؛ سریال جعلی ساخته‌شده با کلید قدیمی رد شد. **یادآوری امنیتی:** توکن Cloudflare که در گفت‌وگوی قبلی افشا شده باید از داشبورد Cloudflare باطل شود؛ دوباره از آن استفاده نکنید.

## ۵. کارهای بعدی و احتیاط‌ها

- هدف ۱۰۰۰ بیماری: **۴۶۳** بیماری دیگر لازم است. از ۹ فصل برنامه‌ریزی‌شده، ENT نخستین فصل تکمیل‌شده است؛ هشت فصل برنامه‌ریزی‌شده هنوز مانده‌اند.
- فصل‌های بعدی را با همین ممیزی یکتایی، دوزبانه‌بودن، red flags، نسخهٔ واقعاً لازم و `npm run hms:regimens` پیش ببرید.
- راهنماهای صوتی/تصویری هنوز ساخته نشده‌اند.
- نصب‌کنندهٔ Node.js روی DISC نیست: شبکهٔ محیط ساخت به `nodejs.org` دسترسی ندارد؛ `TOOLS/PUT-NODEJS-INSTALLER-HERE.txt` توضیح می‌دهد فایل MSI را دستی اضافه کنید.
- دو برنامه در `main` کنار هم هستند (HMS Next.js و ASH FastAPI); هیچ‌کدام را برای «تمیزکاری» حذف نکنید و یکپارچه‌سازی میان‌شان هنوز انجام نشده است.
- هیچ‌وقت قاعدهٔ ایمنی را خاموش نکنید؛ برای استثنا، نسخهٔ جایگزینِ بانددار بنویسید.
- پیش از تغییرات دیتابیس شفاخانه، پشتیبان بگیرید. `data/slotly.db` محلی و git-ignored است؛ `data/demo-hospital.db` نمونهٔ مصنوعی و tracked است.

## ۶. فرمان‌های ادامهٔ کار

```bash
npm ci
npm run hms:regimens       # تولید/ممیزی فایل‌های نسخه
npm run hms:catalogue      # درج دوبارهٔ ردیف‌های RX-C/CT در دیتابیس محلی
npm run hms:demo-db        # با برنامهٔ متوقف، تازه‌سازی دیتابیس نمونه
npm run build
npm run check:secrets
npm run hms:verify
npm run release:iso        # ساخت dist/Aybek-DISC-v7 و فایل ISO؛ dist در git نیست
```

برای دیتابیس نمونهٔ تازه در یک محیط پاک، ابتدا `data/demo-hospital.db` را به `data/slotly.db` کپی کنید، سپس `npm run hms:catalogue` و `npm run hms:demo-db` اجرا شود. دیتابیس عملیاتی واقعی را با فایل دمو جایگزین نکنید.
