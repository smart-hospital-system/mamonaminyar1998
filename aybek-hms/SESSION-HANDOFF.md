## ۳. لایسنس — کلید از سورس بیرون رفت

پیش از این، کلید امضای سریال **داخل `lib/hms/license.ts`** بود؛ هر کسی با آن فایل می‌توانست سریال بسازد.

ترتیب جدید (`resolveSecret`):

1. `AYBEK_LICENSE_SECRET` از محیط یا `.env.local` — راه اصلی.
2. `data/license.key` — کلید تصادفی ۳۲ بایتی که در **اولین اجرا** روی همان کامپیوتر ساخته می‌شود (در `.gitignore`).
3. کلید قدیمی فقط برای **اعتبارسنجی** سریال‌هایی که از قبل در `hms_licenses` ثبت شده‌اند؛ هرگز برای امضا.

**تست‌شده:**

- سریال تازه‌صادر‌شده → `valid: true` ✅
- سریال جعلی که با کلید قدیمیِ داخل سورس ساخته شده → **`valid: false`** ✅

## ۵. نکات فنی برای ادامه‌دهنده

- **پایگاه داده:** `node:sqlite`، فایل `data/slotly.db`. پیام `ExperimentalWarning: SQLite` طبیعی است.
- **شماره‌گذاری بیماری:** هر فصل پیشوند خودش را دارد و شماره‌ها درون فصل یکتاست.
- **قواعد ایمنی نسخه:** دو شکل یک مولکول در یک نسخه = `block`؛ تتراسایکلین زیر ۸ سال = `block`. اگر این‌ها را دیدید، **نسخهٔ جایگزین باند بنویسید، نه اینکه قاعده را خاموش کنید** (در ۵ فصل همین کار انجام شد).
- **فرمولری:** نوع `Form` محدود است (`Syrup`, `Suspension`, `Vial`, `Nebule`, `Drops`, `Tablet`, `Capsule`, `Cream`, `Ointment`, `Suppository`, `Sachet`, `Inhaler`). مسیر غیرخوراکی را در فیلد `route` بنویسید، نه در نام شکل.
- **کارهای ناتمام (صادقانه):** ۵۲۳ بیماری باقی‌مانده (۹ فصل)، بستهٔ DISC/ISO، راهنمای صوتی/تصویری، و بازنویسی `README` تحویل.

## ۷. بستهٔ تحویل — ساخته شد

دو فرمان، دو خروجی:

```
npm run release:disc    # dist/Aybek-DISC-v7/      125 MB
npm run release:iso     # dist/Aybek-Hospital-HMS-v7.iso   124.9 MB
```

**ساختار دیسک:**

| پوشه/فایل | چیست |
|---|---|
| `START-HERE.bat` | نصب‌کننده: Node را بررسی می‌کند، برنامه را در `C:\AybekHMS` می‌گذارد، داده‌های موجود را دست نمی‌زند، شورتکات دسکتاپ می‌سازد |
| `HOSPITAL/` | برنامهٔ **از پیش ساخته‌شده** — فقط `node server.js`، بدون npm و بدون اینترنت |
| `HOSPITAL/data/demo-hospital.db` | شفاخانهٔ نمونه با **۴۷۷ بیماری و ۲۸۶۲ نسخه** — بدون هیچ مرحلهٔ seed |
| `SOURCE/` | سورس‌ها به شکل zip (۴۴۶ فایل، ۱۶ MB) |
| `TOOLS/` | `MAKE-ISO.ps1` (ویندوز، IMAPI2) و جای نصب‌کنندهٔ Node |
| `DOCS/` | راهنماها، از جمله `DISC-INSTALL.md` |
| `MANIFEST-SHA256` | هش هر فایل — `sha256sum -c MANIFEST-SHA256` |
| `MANIFEST.txt` | فهرست، اندازه‌ها، تعداد ردیف‌های بالینی |

**چرا از پیش ساخته‌شده:** کامپیوتر شفاخانه اینترنت ندارد و کسی npm اجرا نمی‌کند. `output: "standalone"` در `next.config.ts` فقط سرور و پکیج‌های لازم را برمی‌دارد؛ نتیجه ۱۰۳ MB است و با نصب سادهٔ Node کار می‌کند.

**چرا ISO بدون ابزار بیرونی:** `scripts/make-iso.mjs` خودش ISO 9660 + Joliet می‌نویسد (بدون mkisofs و بدون python). ویندوز شاخهٔ Joliet را می‌خواند، پس نام‌های بلند سالم می‌مانند.

**آزمون‌های انجام‌شده روی همین تصویر:**

- pycdlib تصویر را باز کرد: برچسب `AYBEK_HMS_V7`، Joliet موجود
- هر ۱۹۵۶ فایل از داخل ISO خوانده و با پوشهٔ مبدأ مقایسه شد: **۰ اختلاف**
- پوشهٔ نصب از داخل ISO بیرون کشیده شد، `sha256sum -c MANIFEST-SHA256` → **۱۹۵۴ فایل OK**
- همان نسخهٔ بیرون‌کشیده با `node server.js` بالا آمد: ورود ۲۰۰، `/hms`، `/hms/prescriptions`، `/hms/diseases` همه ۲۰۰ و «۲۸۶۲ نسخهٔ کاتالوگ» در ثبت
- هیچ `slotly.db` واقعی، `license.key` یا `.env` روی دیسک نیست

**آنچه هنوز روی دیسک نیست:** نصب‌کنندهٔ Node.js (`nodejs-*.msi`). شبکهٔ فعلی اجازهٔ دانلود از nodejs.org را نمی‌دهد؛ فایل را دستی در `TOOLS/` بگذارید. تا آن زمان دیسک روی کامپیوتری که Node دارد کامل کار می‌کند و پیام روشن می‌دهد.

**تصویر ISO در git نیست** (`/dist/` در `.gitignore`) — با `npm run release:iso` هر بار بازساخته می‌شود.
